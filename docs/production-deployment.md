# 달잠 계정·수면 기록 서버 전환

2026-11-12 기준. 개인 브랜치 `feature/postgres-render-production`, 통합 기준 `68762198830906c4755edf391dbffa20150c44f8`에서 개발했다. 기존 두 서버 작업 위치와 팀원 소스는 수정하지 않았다.

## 승인된 운영 구성

사용자가 실제 계정·수면 기록 서비스 개발·배포와 월 50,000원 예산을 승인했다. 운영자명과 공개 문의 이메일도 사용자가 제공했다. 카드 등록은 사용자가 직접 완료했다.

- 기존 `daljam` 서비스: Singapore, Docker, 단일 0.5c-512mb, 월 $7, 자동 확장·자동 배포 Off.
- 새 `daljam-postgres`: PostgreSQL 18, Singapore, 0.1c-256mb, 5GB, 월 $7.50. 저장 공간 자동 확장 Off.
- 기본 합계 월 $14.50. 환율·세금·초과 전송량 등은 별도이며 원화 총액의 절대 상한을 보장하는 설정은 아니다. 유료 워크스페이스, 추가 서버, 유료 AI, 도메인은 구매하지 않는다.
- DB 외부 허용 IP 범위 0개. 같은 리전의 서버에서 내부 URL로만 연결한다. 연결값은 소스·문서·로그에 남기지 않는다.
- 실제 서비스 이미지: `Dockerfile.production`. `Dockerfile`은 기존 체험 전용 이미지로 유지한다.
- 운영 구성: `render.yaml`. 중복 서비스를 만드는 Blueprint로 자동 적용하지 말고 기존 서비스 설정을 변경한다. 과거 체험 구성은 `render.demo.yaml`에 보관했다.

## DB·인증·보관 계약

`health_records.connect()`가 명시적으로 PostgreSQL을 선택한다. 설정 오류·연결 실패·이력 불일치에 SQLite로 우회하지 않는다. SQLite는 명시적인 로컬 사용과 격리 시험에만 남겨 두었다. API는 DB 장애에 비밀값 없는 503을 반환한다.

팀원 `postgres_migrate.py`만 운영 실행기로 사용한다. 과거 작업의 별도 `migration_runner.py`는 포함하지 않는다. 체크섬·이름·버전 이력을 읽기 전용으로 확인하는 `inspect_history`를 어댑터와 공유한다. 출시된 0001 SQL 바이트는 변경하지 않았으며 0002에서 계정별 개인정보·건강정보·해외 저장 동의 및 성인 확인 시각을 추가했다. 요청 처리 중 DDL은 실행하지 않는다.

프로세스 관리자는 공개 포트를 열기 전에 마이그레이션을 검증·적용하고 실패 시 종료한다. FastAPI는 loopback 8011만, Next.js만 Render PORT를 사용한다. 어느 자식이든 종료되면 나머지도 종료한다. `/api/sleep/health`는 liveness, `/api/ready`는 PostgreSQL 연결과 적용 이력 readiness다.

가입 시 각각의 동의와 최신 버전을 서버에서도 검사하며 계정과 동의 이력을 같은 트랜잭션에 저장한다. 로그인 토큰 원문은 브라우저 JSON에서 제거하고 HttpOnly·SameSite Strict·Secure 쿠키를 사용한다. 쓰기 Origin을 공개 HTTPS origin과 비교한다. 웹과 모바일 요청 본문 크기를 제한한다.

휴지통은 30일 후 운영 DB에서 제거한다. 계정 탈퇴·영구 삭제는 관리형 복구 정책을 명시적으로 설정한 경우에만 허용한다. 생성한 Render DB 관리 화면에서 확인한 PITR 보관 기간인 7일을 개인정보 안내에 반영했다. 수동 장기 백업은 생성하지 않는다. 복구 시 현재 운영 DB의 삭제 원장을 먼저 안전하게 확보하고 복구 DB에 삭제 요청을 재반영한 후 서비스를 연결해야 한다. 단순히 과거 DB를 서비스에 연결하면 안 된다. 원장에는 건강 내용 대신 종류·식별자·주체·시각만 남긴다.

`COACHING_ENGINE=rules`만 허용하고 자식 환경의 OPENAI_*를 제거한다. 코칭 개인화·화면 구성은 기존 통합 구현을 유지했다. 동기화는 `complete_snapshot=true`인 명시적 전체 스냅샷에 한해 출처에서 누락된 기록을 휴지통으로 옮긴다. 해당 증명이 없는 모바일 버전은 기존 기록을 자동 삭제하지 않는다.

## 실행한 검사

- 최종 Python 전체: 128개 중 124개 통과, 4개 건너뜀. 공식 EDB PostgreSQL 18.6을 임시 영문 경로에 풀고 loopback TLS 시험 클러스터만 사용했다. 실제 서비스 DB·유료 AI는 시험 대상이 아니다.
- 실제 PostgreSQL: 동시 마이그레이션 잠금, 재실행, 체크섬 불일치, 기존 무체크섬 이력 거절, SQL 실패 롤백, 연결 종료를 검증했다. API에서 가입·로그인·계정 격리·동시 업로드·재접속 조회·규칙 코칭·동의 기록·휴지통·복원·영구 삭제·탈퇴를 합성 데이터로 검증했다.
- 건너뜀 4개: 선택 SQL parser, Windows에서의 POSIX SIGTERM, 기본 실행에서 opt-in하지 않은 웹 HTTP 검사 2개. 웹 HTTP 검사 2개는 별도로 실행해 모두 통과했다.
- 실제 standalone HTTP: Origin·HttpOnly 쿠키·토큰 제거·모바일 본문 제한·로그아웃·API 중단 시 502/503·체험 API 전체 차단을 검증했다.
- 프론트 단위 검사 22개 통과. 최종 Next.js 16.4.5 빌드·타입 검사 통과. Windows의 기존 `.next` 잠금으로 최종 로컬 산출물은 `.next-production`을 사용했다. Docker는 깨끗한 빌드 환경에서 기본 `.next`를 만든다.
- 로컬 가입 동의 화면을 브라우저에서 확인했다. 콘솔 warning/error 없음.

시험 클러스터는 Windows 파일 동기화 지연을 피하려고 fsync·동기 커밋을 비활성화했다. 따라서 이번 로컬 시험은 SQL·트랜잭션·재접속 검증이며 물리적 장애 후 내구성이나 클라우드 백업 복구 성공을 입증하지 않는다. 종료하지 못한 시험 클러스터의 파일은 삭제하지 않도록 정리 순서를 보호한다.

## 배포 후 별도 확인할 항목

이 문서는 배포 전 코드 검증 기록이다. 실제 배포 커밋, 클라우드 Docker 결과, 공개 HTTPS에서의 Secure 쿠키·계정 격리·합성 업로드·삭제 검사는 작업 공간 reports에 별도로 기록한다. 모바일 실기기·백그라운드 권한, 장애 복구 리허설, 서비스 부하 시험, 개인정보 안내의 법률 검토는 이번 로컬 결과로 완료했다고 간주하지 않는다. 의료 진단 서비스로 표시하지 않는다.
