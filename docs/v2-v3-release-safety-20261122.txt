Integration
V3 is merged once into a branch based on production. The automatic three-way
merge preserves the production supervisor, push worker loop, shutdown handling,
service worker, A UI, APK and Docker push defaults. No conflict markers occurred.
The merged Dockerfile includes the V3 runtime modules and keeps scheduled push
and immediate push tests disabled by default. It also explicitly disables the
Premium demo and Premium AI flags. Production server checks continue to reject
demo checkout, activation, preview and live coaching regardless of those flags.
Premium entry points now require the server's demo_available=true response and
are hidden while loading, on errors and for unavailable/production accounts.
The existing staging demo implementation is retained for later presentation work.

Database diagnostics
The adapter still returns its existing safe 503 contract and never retries writes.
It logs only a fixed operation stage and a fixed SQLSTATE category. SQL text,
parameters, credentials, URLs, accounts, request paths and exception details are
excluded. Connection establishment, catalog loading, schema history verification,
begin/execute/executemany/finish failures can now be distinguished internally.
This does not establish the historical root cause of the reported intermittent 503.
Each operation opens its own connection; prepared plans are disabled. Existing
advisory transaction serialization, 10s lock timeout and 60s query timeout remain.

Deployment gate
Passing synthetic/local/CI tests does not prove a current production backup or
real-phone behavior. Before merging the production PR, verify the actual running
SHA, connected DB and schema history through an authenticated internal path;
obtain a fresh production backup and successfully restore/upgrade it in isolation;
retain the tested recovery image; have the Render administrator confirm the
existing-service budget. Keep scheduled push OFF. No new infrastructure or
OpenAI calls are required for this release. Do not trigger intermediate deploys.

The release status and measured pass/fail/skip counts belong in the PR and final
execution report, not in this source note. This file is not deployment evidence.
