# 달잠 Web Push 검증

## 현재 범위

기존 매니페스트의 `standalone` 표시 모드, 달잠 앱 이름, 아이콘과 `apple-touch-icon`을 사용한다. 서비스 워커는 공개 오프라인 안내 페이지만 저장한다. 인증 API, 개인 기록, 계정별 코칭, HTML 페이지 및 APK 응답은 저장하지 않는다. 새 워커 활성화 시 이전 달잠 오프라인 캐시만 정리한다.

iOS·iPadOS 16.4 이상은 HTTPS 사이트를 Safari 공유 메뉴에서 홈 화면에 추가하고, 달잠 아이콘으로 실행한 뒤 계획 탭에서 테스트한다. 일반 Safari 탭에는 홈 화면 안내만 표시한다. Android는 Push API가 있는 브라우저 또는 설치형 웹앱에서 테스트할 수 있다. 달잠 APK의 Android WebView 브리지는 Health Connect를 제공한다. APK 알림은 별도의 Android 네이티브 권한·전송 경로를 도입하는 작업이다. [WebKit의 iOS Web Push 안내](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/) · [Push API 표준](https://www.w3.org/TR/push-api/) · [Notifications 표준](https://notifications.spec.whatwg.org/) · [VAPID RFC 8292](https://www.rfc-editor.org/rfc/rfc8292)

## 격리된 검증 환경

1. 로컬 또는 HTTPS 격리 스테이징에 테스트 계정과 별도 PostgreSQL을 준비한다. 기존 Render 운영 서비스는 테스트 대상에서 제외한다.
2. PostgreSQL에 `python -m postgres_migrate`를 실행해 `0005_web_push.sql` 다음에 `0006_scheduled_web_push.sql`을 적용한다. 0005 구독은 계정과 연결하고 기존 알림 예약은 모두 꺼 둔다. 기존 브라우저는 계획 탭에서 한 번 다시 연결하면 24시간 인증 세션과 독립된 기기 구독으로 전환된다. 세션 수명은 기존 24시간이다.
3. `requirements-server.txt`로 `pywebpush`를 설치한다. 격리 백엔드는 `DALJAM_ENV=staging` 같은 비운영 값으로 시작하고 아래 비밀 변수를 백엔드에만 주입한다. 기존 FastAPI·Next.js 진입점과 HTTPS 프록시를 사용한다. 운영 런처의 `DALJAM_ENV=production`에서는 별도 계정 허용 목록이 있어야 테스트를 사용할 수 있다.

| 백엔드 환경 변수 | 용도 |
| --- | --- |
| `DALJAM_WEB_PUSH_TEST=1` | PostgreSQL에서 즉시 테스트 발송을 명시적으로 켠다. 기본값은 꺼짐이다. |
| `DALJAM_WEB_PUSH_TEST_ACCOUNT_IDS` | 운영 즉시 테스트를 사용할 전용 계정 ID의 쉼표 구분 목록이다. 운영에서 비어 있으면 즉시 테스트가 꺼진다. |
| `DALJAM_VAPID_PRIVATE_KEY` | P-256 개인 스칼라 32바이트를 URL-safe Base64로 인코딩한 비밀이다. 공개키는 서버에서 파생한다. |
| `DALJAM_VAPID_SUBJECT` | `mailto:` 형식의 운영 담당 연락 주소다. |
| `DALJAM_SCHEDULED_PUSH=1` | 예약 발송 작업을 허용한다. 기본값은 꺼짐이다. 이 값 자체로 반복 작업을 시작하지 않는다. |
| `DALJAM_PUSH_JOB_SECRET` | 예약 작업 전용 Bearer 비밀이다. 32~128자의 URL-safe 값을 시크릿 저장소에서 주입한다. |

4. 홈 화면의 달잠을 열고 테스트 계정으로 로그인한다. 계획 → 취침 준비 알림 → 이 기기 연결로 이동해 허용한 뒤 테스트 알림을 보낸다. 브라우저 요청으로부터 푸시 서비스가 접수했음을 보여준다. 화면을 잠근 상태의 실제 표시 여부는 기기에서 확인한다.
5. 앱 창이 열려 있을 때와 닫혀 있을 때 각각 알림을 눌러 계획 탭이 열리는지 확인한다. 거절, 설정에서 권한 변경, 기기 해제, 계정 전환도 확인한다. 이전 알림은 서버에서 취소할 수 없으므로 테스트 메시지에는 이름·수면 기록·계획 내용이 들어가지 않는다.

## A안 운영 배포 순서

1. 팀원의 승인 이후 홈 UX PR을 먼저 병합하고 해당 커밋을 Render에 배포한다. Render의 Deploys에서 Live 커밋을 기록하고, 모바일 홈·기록 상세·iPhone 가져오기와 `/api/ready`를 확인한다.
2. Render 대시보드에서 웹 인스턴스 요금제, DB의 Recovery 탭과 PITR 범위, 자동 배포 설정을 확인한다. PWA 병합으로 자동 배포가 시작되는 구성이면 팀원이 백업 확인과 환경 변수 설정을 먼저 끝낸다. 스키마 0004 상태에서 승인된 환경에 암호화된 `pg_dump --format=custom` 백업을 보관하고, 별도 DB에서 복원과 계정·수면 기록·코칭 확인을 마친다. 운영 데이터가 담긴 백업은 접근이 제한된 보관소를 사용한다.
3. PWA 통합 PR과 배포 대상 SHA를 팀원이 승인한다. 첫 배포에는 `DALJAM_SCHEDULED_PUSH=0`을 명시하고 작업용 키와 외부 호출 경로를 프로비저닝하지 않는다. 운영 HTTPS에서 테스트할 때는 `DALJAM_WEB_PUSH_TEST=1`과 `DALJAM_WEB_PUSH_TEST_ACCOUNT_IDS`를 함께 설정한다. 후자는 팀원이 만든 전용 테스트 계정 ID의 쉼표 구분 목록이다. 값이 없으면 운영 테스트는 비활성이다. VAPID 개인키와 연락처는 백엔드에만 주입한다.
4. 운영 Docker 런처가 `0005`, `0006`을 순서대로 적용한 후 서버를 시작한다. 대시보드에서 실제 Live SHA와 `/api/ready`를 확인하고, 허용 계정만 웹 구독·즉시 테스트를 사용할 수 있는지 확인한다. 일반 계정에서는 예약 알림이 꺼져 있어야 한다.
5. 실제 iPhone 홈 화면 앱에서 알림 허용, 구독, 열린 상태·잠금 상태·앱을 닫은 상태의 수신, 알림 클릭 후 계획 탭 이동, 구독 해제와 후속 발송 차단을 확인한다. 서버의 푸시 서비스 접수와 기기 수신은 각각 기록한다. 운영 즉시 테스트는 로그인된 해당 설치에서만 시작할 수 있다. 세션 자연 만료 이후 수신은 별도 HTTPS 격리 계정의 예정 창에 작업을 한 번 실행하여 확인한다.
6. 예약 실기기 결과와 스케줄러 지연·콜드 스타트·배치 처리량을 검토하고 팀원 승인 후 실제 발송을 활성화한다. 승인 전까지 운영 스케줄러와 예약 플래그를 꺼 둔다. 운영 즉시 테스트가 끝나면 테스트 플래그를 끄고 허용 목록을 제거한다.

## 롤백

- 알림 동작만 문제라면 실행기를 중지하고 두 발송 플래그를 모두 `0`으로 설정해 현재 호환 코드로 배포한다. 이미 제공자가 접수한 알림은 회수할 수 없다.
- 앱 코드 롤백이 필요하고 DB가 건강하면 마지막으로 검증한 A안 소스에 후보의 0005·0006 SQL과 manifest만 반영한 호환 빌드를 준비한다. 격리 DB에 0006이 적용된 상태에서 시작·로그인·조회·쓰기를 검증하고 Linux에서 다시 빌드한 뒤 팀원 승인을 받아 사용한다. 일반 Render 서비스 롤백은 DB 스키마에 영향을 주지 않는다. 0004·0005까지만 아는 빌드는 0006 DB에서 시작할 수 없다.
- 스키마나 데이터 복구가 필요하면 쓰기 중단 시점을 먼저 정한다. 검증한 백업 또는 PITR로 **별도 DB**에 복원한 뒤 데이터 검증과 백업 이후 쓰기 유실 범위 확인을 마치고 연결을 전환한다. 새 복구 인스턴스에서 발생할 비용은 실행 전에 확인한다. [Render 백업과 PITR](https://render.com/docs/postgresql-backups) · [Render 서비스 롤백](https://render.com/docs/rollbacks)

구독 endpoint와 브라우저 키는 백엔드 DB에 보관한다. 인증 API의 기기 목록에는 식별용 해시, 등록 시각과 상태만 포함한다. 제공자별 HTTPS 주소 범위를 검사하고 리다이렉트를 금지한다. 테스트 발송에는 로그인과 해당 기기의 설치 식별자가 필요하다. 계정당 1분에 한 번, 전체 1분에 20회, 계정당 8기기로 제한한다. 제공자의 404·410은 만료된 구독으로 처리한다.

## 취침 30분 전 예약 작업

예약 작업은 한 번 실행하는 내부 FastAPI `POST /internal/web-push/run`으로 구현되어 있다. 기본 비활성이며 반복 스케줄러는 연결 대기 상태다. 이 경로는 공개 Next.js 프록시에서 제외된다. 격리 환경에서 백엔드의 루프백이나 비공개망에서 작업용 Bearer 비밀을 써서 호출한다. 외부 스케줄러를 선택한다면 정확히 이 작업만 호출할 수 있는 HTTPS 진입점과 자격 증명 회전을 별도로 마련한다. 전체 FastAPI를 외부에 공개할 필요는 없다.

- 저장된 IANA 시간대에서 **취침 목표일**의 취침 시각을 해석한 후 UTC로 변환해 실제 경과 시간 30분을 뺀다. 목표가 00:15면 전날 23:45에 알림이 올 수 있다. DST로 목표 시각이 사라지면 다음 유효 현지 시각, 중복되면 첫 번째 발생 시각을 선택한다.
- 브라우저의 HttpOnly 설치 쿠키는 1년 유효하며 인증 토큰을 대신하지 않는다. 세션 만료로 기기 구독이나 예약 동의는 해제되지 않는다. 명시적 로그아웃과 같은 설치에서 다른 계정으로 전환하면 그 설치의 이전 구독을 해제한다. 다른 기기는 유지된다. 계정 삭제는 활성 구독과 발송 이력을 함께 제거한다. 브라우저 데이터 삭제나 푸시 제공자 만료로 구독이 끊어지면 계획 탭에서 다시 연결하고 확인한다.
- 취침 목표를 실제 저장한 계정에서 해당 기기의 알림을 따로 켠다. 실행 시 최신 목표와 설정을 읽고 제공자 요청 직전에 다시 확인한다. PostgreSQL 트랜잭션과 계정·설치·현지 취침일, 계정·구독·현지 취침일 제약으로 동시 실행·재시작의 중복을 막는다. 이미 접수된 알림은 설정을 꺼도 취소할 수 없다.
- 예정 시각부터 10분 동안만 최대 8건씩 시도한다. 명확하게 거부된 HTTP 429는 2분 이후 유효 창 안에서 한 번 더 시도할 수 있다. 타임아웃이나 중간에 중단된 요청은 접수 여부가 불명이라 자동 재전송하지 않는다. 404·410과 명시적 만료 구독은 정리한다. 접수 결과는 단말 수신 보장을 의미하지 않는다. 푸시 TTL은 최대 60초, 발송 이력 보관은 14일이다. 격리 환경에서 실제 부하 및 발송 예정 창 안의 배치 처리량을 확인한다.

| 방식 | 비용과 정확도 | 운영 특성 |
| --- | --- | --- |
| Render 웹 프로세스 내부 루프 | 무료 인스턴스는 15분 유휴 후 휴면에 들어가므로 예약 실행이 누락될 수 있다. 이미 유료 웹 인스턴스를 쓰면 별도 서비스 비용 없이 후보가 되지만 재시작과 배포 중단은 남는다. | 구현 부담이 적다. 복제본 간 DB 잠금, 영구 발송 이력, 오류 모니터링과 지연 허용 범위가 필요하다. |
| GitHub Actions에서 인증된 작업 호출 | 기존 무료 사용 범위에서 스테이징 실험이 가능하다. 최소 간격은 5분이며 지연·누락과 Render 콜드 스타트가 겹칠 수 있다. | 시간대별 대상은 서버에서 배치 조회한다. 작업 전용 자격 증명, 재생 방지, 회전, 기본 브랜치 실행 조건, 일시 정지 모니터링이 필요하다. 사용자 세션 토큰이나 VAPID 키를 워크플로에 전달할 필요는 없다. |
| 별도 스케줄러 또는 외부 실행기 | Cloudflare Workers Free는 계정당 Cron Trigger 5개, 일일 요청 최대 10만 건, Cron 실행당 CPU 10ms 제한이 있다. Render Cron은 작업당 월 최소 비용이 있다. | 간단한 HTTPS 호출을 분리할 수 있다. Render의 휴면 복귀와 호출 지연은 남는다. 비밀 보관, 실패 가시성, 할당량 점검이 필요하다. |

무료 환경에서는 GitHub Actions를 격리 스테이징의 호출 검증에 먼저 활용한다. 일정 실행은 기본 브랜치에 워크플로가 있어야 하며 최소 간격 5분은 발송 지연 상한이 아니다. 팀이 별도 무료 스케줄러를 선택하면 휴면 복귀 시간과 누락률을 측정한 뒤 활성화한다. 기존 유료 웹 인스턴스가 확인되면 별도 결제 없이 내부 주기 실행을 평가할 수 있다. 실기기 검증에서는 HTTPS 홈 화면 앱에서 테스트 알림을 먼저 받고, 취침 목표와 시간대를 저장한 뒤 예약 알림을 켠다. 격리 작업을 예정 창에 호출해 화면을 잠그거나 앱을 종료한 상태에서 수신과 계획 탭 이동을 확인한다. 같은 설치에서 24시간 세션 자연 만료 후 수신, 재로그인 후 구독 유지, 명시적 로그아웃과 다른 기기의 수신 유지, 해제 후 미발송을 각각 확인한다.
