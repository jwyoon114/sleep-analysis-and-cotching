# 실제 기록을 사용하는 Premium AI 시연

## 동작과 활성화 범위

Premium 모의 결제 → 시연 권한 활성화 → 수면 시작·종료 직접 입력 → 기존 수동 기록 API에 저장 → `AI 맞춤 조언 생성` 순서로 사용한다. 기존 자동 연동 기록도 선택할 수 있다. 일반 `/coach`와 Health Connect 자동 코칭은 기존 무료 규칙 경로를 사용한다. 실제 모델 호출은 인증된 `/premium/demo/coach` 요청에서만 가능하다.

기본 상태에서는 실제 API를 호출하지 않고 준비된 샘플을 제공한다. 비운영 환경에서 비용 승인을 받은 운영자가 서버 설정을 모두 준비해야 실제 요청 경로를 활성화할 수 있다. `production`에서는 시연 발급과 실제 시연 호출을 차단한다. 이번 개발 검증은 SDK 모의 응답만 사용했으며 실제 OpenAI 프로젝트·결제·크레딧 설정을 변경하지 않았다.

| 서버 환경변수 | 값과 용도 |
| --- | --- |
| `DALJAM_ENV` | `development`, `test`, `staging` 중 승인된 비운영 환경 |
| `DALJAM_PREMIUM_DEMO` | 기존 모의 결제 시연 활성화 시 `1` |
| `DALJAM_PREMIUM_AI_ENABLED` | 기본 비활성. 비용·설정 승인 후 `1` |
| `OPENAI_API_KEY` | 별도 개발 프로젝트의 서버 전용 키. 저장소·브라우저·로그에 기록하지 않는다 |
| `OPENAI_PROJECT_ID` | 별도 개발용 프로젝트 ID. SDK의 `project` 인자로 전달 |
| `OPENAI_MODEL` | 승인한 모델 이름을 명시. 이 시연 경로는 기본 모델을 자동 선택하지 않는다 |
| `DALJAM_PREMIUM_AI_USAGE_DB` | 기존 앱 DB와 별개인 사용량 SQLite 파일의 절대 경로. 부모 폴더를 미리 준비하고 서버 쓰기 권한을 확인 |
| `DALJAM_PREMIUM_AI_MAX_INPUT_TOKENS` | 기본 8192, 허용 2048~16000의 보수적 입력 예산 |
| `DALJAM_PREMIUM_AI_MAX_OUTPUT_TOKENS` | 기본 1000, 허용 128~1400. Responses API의 `max_output_tokens`로 전달 |

키·프로젝트·모델·장부 설정이 누락되거나 잘못되면 샘플 모드로 동작한다. 실제 호출 경로는 `.streamlit/secrets.toml`을 읽지 않으며 OpenAI 공식 API 주소를 명시해 환경의 다른 API 주소를 사용하지 않는다. 별도 개발 프로젝트인지 여부와 키의 해당 프로젝트 권한은 운영자가 승인 과정에서 확인한다. 일반 코칭 설정 `COACHING_ENGINE`은 `rules`로 유지할 수 있다. 기존 운영 시작 스크립트와 Render 설정은 이번 작업의 변경 대상에 포함되지 않는다.

## 입력·출력과 개인정보

`manual_coaching`의 14일 이전 기록 선택, 중복 구간 제외, 서버 수치 계산, 표현 설정 스냅샷과 구조화 응답 검증을 재사용한다. 수동 기록은 입력 시각·시간대·추정 수면 시간과 실제 저장된 이전 기록의 시각을 사용한다. 자동 기록은 확인된 시작·종료 시각, 측정 구간 길이와 수면 분류 시간을 사용한다. 측정 구간을 실제 수면 시간으로 해석하지 않는다.

말투·강도·MBTI·비속어 허용은 서버 저장 설정을 사용한다. 캐릭터는 전송하지 않는다. 계정 ID·기록 ID·기기명·원시 구간·단계별 비율·생체지표도 이 요청의 외부 입력에서 제외한다. 모델은 실천 제안·선택 확인 질문을 작성하며 관찰과 수치는 서버가 작성한다. 측정되지 않은 정보나 진단 표현·새 숫자가 포함된 응답은 기존 검증에서 대체 처리한다.

입력은 지침·JSON 요약·출력 스키마의 UTF-8 바이트 수에 프레이밍 여유 1024를 더한 보수적 상한으로 검사한다. 정확한 모델 토크나이저 계수와 구분하며, 이 검사를 통과한 입력만 전송한다. 공급자가 보고한 실제 토큰 사용량은 별도 기록한다. 승인한 모델의 실측 입력량과 이 예산의 관계는 최초 실모델 검증에서 확인해야 한다. 출력은 `max_output_tokens`로 제한한다. SDK 타임아웃은 30초이며 자동 재시도는 0회다. `store=False`를 적용한다. 관련 API 항목은 [OpenAI Responses API 문서](https://developers.openai.com/api/reference/python/resources/responses/methods/create)를 참고한다.

## 사용량과 중복 방지

계정별 실제 요청 예산은 서버 시각을 기준으로 최근 24시간에 최대 3회다. 고정 UTC 달력일 대신 이동 구간을 사용하므로 시간대나 목표 취침 시각을 바꿔 한도를 초기화할 수 없다. 일반 무료 조언과 샘플 조회는 이 예산을 소모하지 않는다.

사용량 장부는 명시한 비운영용 SQLite 파일이며 앱 PostgreSQL의 대체 저장소로 사용하지 않는다. 기존 운영 스키마에는 새 마이그레이션을 추가하지 않았다. PWA 브랜치의 `0005`, `0006` 번호를 확인한 후 이 작업에서는 별도 장부를 선택했다. 장부는 전용 application ID·스키마 버전을 확인하고 기존 다른 DB 파일을 덮어쓰지 않는다.

장부의 계정 키는 계정 ID의 SHA-256 값이다. 요청 UUID, 입력 지문, 기록·코칭 참조 ID, 시각, 상태, 모델, 입력 예산과 공급자 토큰 수만 기록한다. 건강 기록 원문·조언 본문·API 키·제공자 오류 원문은 장부에 저장하지 않는다. 주 DB의 생성 문장·설정·근거 저장은 기존 코칭 이력 구조를 재사용한다.

`BEGIN IMMEDIATE` 트랜잭션에서 예약·중복·24시간 한도를 함께 검사한다. 동일 계정의 요청 UUID는 입력에 고정되며 다른 입력으로 재사용하면 409를 반환한다. 다른 UUID라도 최근 24시간에 같은 기록·요약·표현·모델·출력 예산으로 요청하면 기존 결과를 재사용한다. 처리 중인 중복 요청에는 409를 반환하고 자동으로 모델을 재호출하지 않는다. SDK 직전에 중복·예산을 다시 검사하고 발송 시각을 영구 기록한다. 24시간 구간은 발송 시각을 우선 사용해 예약과 발송 사이에 지연이 있어도 한도를 지킨다. 자동 재시도는 사용하지 않는다.

공급자 타임아웃·인증·연결·사용량 제한 오류도 시도한 호출 예산에 포함한다. 사용량을 받지 못하면 토큰 값을 알 수 없음으로 보존한다. 합계에는 확인된 토큰만 반영하고 미확인 요청 수를 함께 반환한다. SDK 호출 이전의 입력 예산 초과는 규칙 기반 결과를 저장하며 실제 호출 예산을 소모하지 않는다.

시연 초기화·재로그인·권한 재발급은 장부의 예산을 초기화하지 않는다. 서버 재시작 후에도 동일 장부 파일을 사용해야 한다. 비정상 중단된 요청을 자동 재전송하지 않으며, 미확정 예약은 보수적으로 예산에 포함될 수 있다. 앱 코칭 저장 후 장부 완료 직전에 중단되면 예약한 코칭 ID로 저장 결과를 찾아 복구한다. 장부 경로 변경·삭제는 예산 초기화로 이어지므로 실제 시연 중에는 고정된 파일을 유지한다.

시연 권한은 기존 단일 프로세스 메모리에서 관리한다. 장부는 같은 파일을 공유하는 단일 호스트의 중복 호출을 방지한다. 여러 호스트에서 실제 서비스를 운영하려면 권한과 장부를 공통 영구 저장소로 통합하는 후속 작업이 필요하다.

## 모의 검증과 최초 실제 호출 준비

`python -B -m unittest discover -s tests -p test_premium_live_coaching.py -v`는 임시 DB와 SDK 모의 응답으로 실행한다. `python -B tests/premium_browser_fixture.py --mode staging --mock-live`는 일회용 PostgreSQL과 별도 임시 장부에서 성공·타임아웃 응답을 모의 처리한다. 이 옵션은 실제 키를 사용하지 않는다. 기존 `--mode staging`, `--mode production` 검사는 기본 샘플 및 운영 차단을 확인한다.

실제 호출 전에 다음을 승인·확인한다.

1. 별도 개발 OpenAI 프로젝트와 해당 프로젝트 전용 키·모델 접근 권한을 준비한다. 모델별 현재 단가와 입력·출력 예산, 하루 3회 시도의 예상 비용을 검토하고 사용자의 비용 승인을 받는다.
2. 개발 프로젝트의 사용량·비용 확인 방법과 예산 설정을 검토한다. 이 구현은 계정별 호출·토큰 예산이며 전체 사용자 월간 금액 상한은 별도 후속 정책이다.
3. 고정된 장부 경로·쓰기 권한·보관 및 시연 종료 후 폐기 방식을 정한다. 운영 DB 파일과 분리한다.
4. 승인 후 비운영 API 서버에만 필요한 비밀값과 활성화 설정을 적용한다. 실제 건강 요약의 외부 전송 안내와 동의를 확인한다.
5. 제한된 계정에서 최초 한 건의 실제 응답·화면 표시·실제 토큰 사용량·개발 프로젝트 비용을 대조한다. 모델 문장에 근거 없는 측정·의학적 판단·모욕 표현이 없는지 확인한다.

이번 개발에서는 이 실제 호출 절차를 실행하지 않는다. 공식 운영 설정 참고 자료는 [OpenAI 운영 가이드](https://developers.openai.com/api/docs/guides/production-best-practices)에 있다.
